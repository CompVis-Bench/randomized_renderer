# 合成扩充样本的标注约定

本次扩充遵循用户最终确认的 **v3**，而不是 basis 中另附文档的 v5 外部编码结构。

- 每张图片对应一份 JSON，保留 `schema_version`、`sample_id`、`charts`、`data_fields`、`image_observation`。
- `schema_version` 为 `chart_encoding_variation_only_v3`。
- `link` 额外包含 `link_targets`，指向实际连接的节点模板；其他类型不含该属性。
- 每个普通图表含 `chart_id`、`variation`、`encodings`、`repetition_position`。
- `repetition_position` 只记录定位整个重复模板的匿名字段 ID，去重，不记录外部 size/color。
- 内部的 color、size、shape 等仍按真实数据绑定标注。统一的固定点形状、调色盘、字体和固定饼图半径不增加字段。
- 同一模板的重复实例只标一次；不同变量的独立图表分别标注。
- 嵌套模板继承实际可观察的父级定位字段；嵌套外还有分面时，合并外层分面字段。
- 隐藏的定位散点不是可见图表，不单独标成 point。
- 匿名字段 ID 在整张图中保持身份一致。角度编码与整个饼图的定位字段必须区分。
- 固定饼图/环图样式变化保留 `pie/donut/radial_bar` 类型。径向扇区柱、径向矩形柱也使用此归一化类型，但要保留实际的 theta/radius 编码，不得按 Pie 的数值角度绑定套用。
- Polar Facet 的模板内部 theta/radius 与角向/径向分面因子分开标注；分面因子只进入 `repetition_position`。Polar Concat 本身不增加重复字段。
- 多层 Nested 逐层收集实际定位字段。例如柱图嵌到 F1/F2，饼图又嵌到柱端时，饼图还继承柱类别和柱端数值字段；不能只按层数填字段。
- 先 Concat 再 Nested 时，使用实际被选中作为父级的图表字段；相邻但未参与定位的图表不贡献重复字段。

这些样本先指定目标标注，再由显式构造计划生成 spec 和图片。编译器验证字段映射和重复位置集合；自动检查不替代视觉复核。manifest 的 `generated_pending_review` 表示待复核，不能作为所有语义都已人工确认的声明。

原生 VisBricks 目标编译器支持有限子集；完整来源扩展和新增空间嵌套批次使用显式标识的离线 D3 适配器。适配器按标注与构造计划渲染合成数据，不自动恢复来源图像的原始数据或完整布局。具体支持范围见工具 README 和各批次构建说明。


扩展结构仍遵循 v3：

- 树模板使用 `tree`（兼容编译 `dendrogram`）；横向字段表示按层级排序的节点身份，纵向字段为经过父子结构验证的深度。节点内嵌小图继承这两个位置字段及外层 Facet 字段。
- Treemap 内部标注面积 size 和数据 color；父子键属于构造关系，不因存在内部结构而增加 repetition_position。
- Sunburst 的 theta 是质量，radius 是层级深度；独立于外层主题分面的位置字段。
- 力导网络拆成实际节点 glyph（当前 point，color/size）和 link；任意力导屏幕位置不证明存在 x/y 数据字段。整网络分面时两者继承分面字段。
- 平行坐标的 x 对应维度名，y 对应长表中的维度数值；构造时透视为多个原生轴，不把每条记录算作 Facet。
- 地图分别标 geo_area 和 geo_point 的实际数据编码。地理边界为结构；无独立数值绑定的边界位置不编造字段。无数据编码的背景也不增加模板。
- Stacked Area 保留 stacked_area；参考图里的 Horizon 并没有被标成 stacked_area。新样本的标签依据实际构造，而非仅继承参考图的名称。

新增空间嵌套批次另遵循以下规则：

- Nested 必须落在真实父级轴、节点、散点位置或单元格内，单纯共享字段不算 Nested。轴上方小图的水平中心必须对准对应轴，并与轴内叠加的小图区分记录。
- 节点容器可以承载完整的 Overlay/Concat 子树。容器的中心编码父级位置，边框保留父级节点类别的颜色；内部小图使用自己的编码与坐标。
- Graph 的任意布局不新增 x/y 数据字段；图内子图按实际节点身份重复，节点身份字段进入子图的 repetition_position。
- Treemap 单元格中的子图按实际叶节点身份重复。单元格本身仍标 size/color；父子身份不伪装成内部 x/y 编码。
- Heatmap 子图继承矩阵行列定位字段；tree 子图继承实际的深度与节点身份定位字段。横向 tree 与矩阵或条形图对齐时使用同一叶节点顺序和行中心。
- 平行坐标的轴附属小图继承维度身份字段。轴内 boxplot 使用该维度的同一数值变量和垂直尺度，其样本来自父图记录。
- 父级定位时间与节点内部时间序列不是同一变量时，必须使用不同字段，避免继承时把内部 x 变成常数。
- 对外仍使用 v3；构造说明保存结构层级、共享尺度和实际锚点，SVG 中保留不可见的几何检查属性。

## 2026-09-24：空间证据要求

扩充数据中，相同字段 ID 跨 MG/RMG 使用即声明 data field relation。仅数据列同名或取值相同不够；必须有共享轴、对齐的重复单元、共同 facet/nested 定位或同坐标层等可见位置证据。共享 x 上下排列、共享 y 左右排列；共享 theta 在同一圆心按环带内外排列。不能建立兼容映射时，保留编码通道，拆分字段身份，并同步构造计划。此修订优先于较早的生成说明。
